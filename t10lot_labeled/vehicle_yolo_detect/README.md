# Vehicle detection dataset

Single class (`vehicle`), 190 frames at 1600x900, YOLO format.
Generated by `build_vehicle_dataset.py` in the author's application repository.
Do not edit by hand.

## Where the labels came from

200 frames were sampled from the camera archive and pre-labelled with stock COCO
YOLO weights, then corrected by hand in makesense.ai. The corrected export
`labels_yolo_det_data_2026-07-29-07-45-54.zip` is the only source of boxes used
here. The export is held in the author's application repository and is not
shipped with this dataset.

The COCO bootstrap labels from the pre-labelling pass are superseded. They are
the uncorrected machine output and are not read by the build script.

## Frames without a label file

184 of the 200 frames came back with a label file. The remaining 16 were
inspected and fall into two groups.

Six are genuinely empty daylight lots. They are included with empty `.txt`
files, as real negatives that help suppress false positives:

- `2026-03-29_0650`
- `2026-03-29_1000`
- `2026-03-29_1310`
- `2026-03-29_1620`
- `2026-03-29_1930`
- `2026-04-14_1053`

Ten are night frames that do contain vehicles the annotator could not see in the
image. They are excluded from the dataset entirely and appear in neither split:

- `2026-02-27_1851`
- `2026-03-04_1821`
- `2026-03-24_1858`
- `2026-04-01_1943`
- `2026-04-14_2003`
- `2026-04-16_2022`
- `2026-04-22_2055`
- `2026-04-27_2054`
- `2026-04-29_2032`
- `2026-04-30_2053`

They are excluded because a COCO pass at confidence 0.05 finds one to six vehicles
in most of them. Labelling them empty would teach the detector that vehicles at
night are background. That would undo the hand correction done on the 14 night
frames that are properly labelled. The absent label file records annotator
visibility, not an empty lot.

Final size: 184 labelled + 6 empty = 190 frames.

## Split

The split is by capture day, not by frame. Frames from one day share lighting,
weather and largely the same parked cars, so a random split would place near
duplicates on both sides of the split and inflate the validation metric. Whole
days are assigned, so no day contributes to both splits.

Days are walked in date order. A day goes to val whenever val is below its 20%
share. This spreads validation across the whole capture period.

- train: 34 days, 149 frames (78%)
- val: 9 days, 41 frames (22%)

Val days: 2026-02-24, 2026-03-03, 2026-03-10, 2026-03-17, 2026-03-26, 2026-03-31, 2026-04-09, 2026-04-21, 2026-04-30

Train days: 2026-02-20, 2026-02-25, 2026-02-26, 2026-02-27, 2026-03-02, 2026-03-04, 2026-03-05, 2026-03-06, 2026-03-09, 2026-03-11, 2026-03-12, 2026-03-13, 2026-03-18, 2026-03-19, 2026-03-20, 2026-03-24, 2026-03-25, 2026-03-27, 2026-03-28, 2026-03-29, 2026-03-30, 2026-04-01, 2026-04-02, 2026-04-07, 2026-04-08, 2026-04-13, 2026-04-14, 2026-04-15, 2026-04-16, 2026-04-20, 2026-04-22, 2026-04-27, 2026-04-28, 2026-04-29

Both splits contain night frames (mean luminance below 20), which is the hard
case for this camera. A val set without night frames would not measure it.
